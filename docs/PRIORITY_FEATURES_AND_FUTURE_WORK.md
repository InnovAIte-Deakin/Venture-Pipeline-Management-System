## Purpose

This document records important features, unresolved bugs, technical improvements, and unfinished work that should be considered by the next VPMS team. It keeps future work in one place so new members can understand what remains, why it matters, and where to find supporting evidence.

## How to use this document

1. **Choose the correct section.** Add the item under Frontend, Backend, or Shared / Integration / DevOps.
2. **Describe remaining work.** Record what still needs to be completed, not a list of past personal contributions.
3. **Set the priority and status.** Use the agreed labels so the next team can quickly plan its work.
4. **Add evidence.** Include a Planner task, GitHub issue, pull request, document, screenshot, or other useful link whenever possible.
5. **Keep entries accurate.** Check for duplicates and update an existing row when its status changes.

## Priority and status guide

| Label | Meaning |
|---|---|
| **High** | Blocks a core workflow, affects security or data, or is required for a usable release. |
| **Medium** | Provides a meaningful improvement to usability, maintainability, performance, or testing. |
| **Low** | A useful enhancement that can be scheduled after essential work. |

**Status:** `Proposed`, `Not started`, `In progress`, `Blocked`, or `Ready for handover`.
