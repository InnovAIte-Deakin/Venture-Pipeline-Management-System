# Project Overview  
## Venture Pipeline Management System (VPMS)

### Organisation  
Mekong Inclusive Ventures (MIV)

---

# 1. Overview

The Venture Pipeline Management System (VPMS) is a Minimum Viable Product (MVP) developed to support Mekong Inclusive Ventures (MIV) in managing and tracking early-stage ventures throughout the investment and support pipeline.

VPMS provides a centralised platform where founders can submit venture information and supporting documentation, while administrators can review, assess, and monitor venture readiness through a structured and transparent workflow.

The system is designed to improve operational visibility, reduce administrative inefficiencies, and support more consistent decision-making across the venture lifecycle.

---

# 2. Problem Context

Prior to VPMS, venture management relied heavily on fragmented tools and manual processes, resulting in:

- Limited visibility into venture progress
- Inconsistent review and assessment workflows
- Increased administrative overhead
- Reliance on ad-hoc communication channels
- Difficulty maintaining centralised documentation

These challenges reduced efficiency and made it difficult to track venture development consistently across stakeholders.

---

# 3. Proposed Solution

VPMS addresses these challenges by:

- Centralising venture data and documentation
- Standardising submission and review workflows
- Providing clearer visibility into venture progress
- Enabling role-based access control
- Supporting both desktop and mobile user experiences
- Improving accessibility for users with varying levels of digital literacy

---

# 4. Platform Strategy

VPMS adopts a dual-platform approach to support different user groups and operational requirements.

## Web Platform (Admins & Founders)

The web platform provides a full-featured interface for:
- Venture submissions
- Pipeline management
- Review workflows
- Document management
- Administrative oversight

## Mobile Platform (Impact Users)

The mobile platform focuses on accessibility and usability for impact users by providing:
- Simplified navigation
- Reduced cognitive load
- Clear and readable interfaces
- Minimal interaction complexity
- Mobile-first accessibility considerations

Both platforms operate on a shared backend and data layer to ensure consistency across the system.

---

# 5. Goals and Objectives

## Primary Goal

To provide an accessible, intuitive, and scalable platform that supports venture pipeline management for diverse stakeholder groups.

## Key Objectives

- Centralise venture documentation and records
- Support structured and transparent review workflows
- Improve visibility into venture progress and readiness
- Enforce secure role-based access control
- Deliver an accessible mobile experience for impact users
- Support future scalability and deployment readiness

---

# 6. Intended Users

| User Group | Responsibilities | Platform |
|---|---|---|
| Founders | Submit and manage venture data | Web |
| Admins | Review ventures and manage pipeline workflows | Web |
| Impact Users | Access simplified venture information | Mobile |
| Developers | Maintain and extend the system | Both |

---

# 7. Accessibility Focus

Accessibility is a core consideration within VPMS, particularly for mobile experiences and users with lower levels of digital literacy.

Key accessibility priorities include:
- Simplified user flows
- Clear visual hierarchy
- Readable typography and layouts
- Reduced cognitive load
- Consistent navigation patterns
- Mobile-first usability considerations

---

# 8. Current MVP Scope

The current MVP includes:

- Authentication and user management
- Venture submission workflows
- Document upload and storage
- Venture tracking and status monitoring
- Review and assessment workflows
- Role-based access control
- Mobile-accessible interfaces for impact users

---

# 9. Project Context

VPMS is being developed as part of a capstone initiative in collaboration with Mekong Inclusive Ventures (MIV).

Development is guided by stakeholder requirements, Product Requirements Documentation (PRD), and prior project handover materials, with a focus on producing a scalable and deployment-ready foundation for future development.
