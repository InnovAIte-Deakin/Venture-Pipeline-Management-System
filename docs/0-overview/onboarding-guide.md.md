# VPMS Contributor Onboarding Guide  
*(For Future Contributors & Junior Team Members)*

---

# 🧭 Overview

Welcome to the **VPMS (Venture Pipeline Management System)** project.

This guide is designed to help future contributors understand:
- How the project operates  
- How workflows are managed  
- What is expected throughout the trimester  
- How to contribute effectively within the team  

The goal of this guide is to reduce confusion, improve collaboration, and help contributors gradually become comfortable with the project environment.

This onboarding guide is based on experiences, workflows, and challenges observed during previous trimesters.

---

# 🌱 About the Project

The Venture Pipeline Management System (VPMS) is designed to support impact users and MSMEs throughout different stages of the venture pipeline process.

The platform helps manage:
- Venture onboarding  
- Application submissions  
- Document handling  
- Venture review workflows  
- Meetings and communication  
- Pipeline progression and decision-making  

The project involves collaboration across multiple streams, including:
- Frontend development  
- Backend development  
- Documentation  
- UI/UX design  
- Research and analysis  

---

# 👥 Team Structure

The project typically includes:
- Product Owner (PO)  
- Mentors  
- Frontend contributors  
- Backend contributors  
- Documentation contributors  
- UI/UX contributors  

Contributors may work across multiple streams depending on project requirements and individual strengths.

# 📅 Week 1–3 — Setup & Understanding the Project

---

# 🔧 Environment Setup

During the first few weeks, contributors should focus on setting up the required development environment and understanding the overall structure of the project.

Students should install and configure:
- Node.js (Latest LTS version)  
- Visual Studio Code  
- GitHub account  
- Git  
- Docker (if required for backend setup)  

Students should also ensure they receive:
- GitHub repository access  
- Figma access  
- Microsoft Teams access  
- Meeting invitations and stream access  

---

# 📖 Understanding the Project

Before contributing, students should spend time understanding:
- The purpose of VPMS  
- The target users of the platform  
- System workflows  
- UI structure and navigation  
- Existing project documentation  

Students are encouraged to:
- Explore the Figma designs  
- Review previous documentation  
- Understand how different streams collaborate  

---

# 👥 Meetings & Participation Expectations

Students are expected to regularly attend:
- Weekly 1-on-1 mentor meetings  
- Stream meetings (Frontend / Backend / Documentation)  
- Product Owner (PO) meetings  
- Team collaboration meetings  
- Technical onboarding sessions  

Regular attendance is important for:
- Understanding project direction  
- Clarifying assigned tasks  
- Receiving feedback  
- Staying aligned with the team  

---

# 💬 Communication Expectations

Contributors are expected to:
- Check Microsoft Teams regularly  
- Respond professionally to messages  
- Inform mentors/team members about blockers early  
- Share progress updates consistently  

Poor communication may lead to:
- Confusion about tasks  
- Delayed contributions  
- Missed updates or meetings  

---

# 🎓 Workshops & Learning Sessions

Students are encouraged to attend all workshops organised during the trimester.

Examples include:
- GitHub workshops  
- Git/version control sessions  
- Pull Request workflow sessions  
- Technical onboarding workshops  
- Collaboration and workflow sessions  

These workshops are especially important during the first 4–6 weeks and help contributors understand the expected workflow within the project.

---

# 🧠 Common Challenges During Week 1–3

New contributors may:
- Feel overwhelmed by the project size  
- Struggle to understand where to begin  
- Feel hesitant to ask questions  
- Confuse frontend, backend, and documentation workflows  

---

# ✅ How to Overcome These Challenges

- Ask questions early  
- Attend meetings consistently  
- Review documentation carefully  
- Explore Figma before contributing  
- Start with smaller tasks first  

Contributors are not expected to understand everything immediately.

---

# 📅 Week 4–6 — Initial Contributions & Mid-Trimester Progress

---

# 🚀 Beginning Contributions

By this stage, contributors are expected to begin making smaller but meaningful contributions to the project.

Examples include:
- UI improvements  
- Documentation updates  
- Minor bug fixes  
- Content and layout adjustments  
- Workflow refinements  

Students should begin becoming familiar with:
- GitHub workflows  
- Pull Requests (PRs)  
- Branch management  
- Team collaboration practices  

---

# 🔁 Pull Request Workflow

Typical workflow:
1. Create a branch  
2. Implement changes  
3. Test locally  
4. Push changes to GitHub  
5. Create a Pull Request (PR)  
6. Address review feedback  
7. Merge approved changes  

Students are encouraged to test their work before pushing changes.

---

# 🏢 Industry Panels & Guest Lectures

Students are encouraged to attend:
- Industry panel talks  
- Guest lectures  
- Networking sessions  
- Capstone support sessions organised by the unit chair  

These sessions help students:
- Understand industry expectations  
- Improve professional communication  
- Learn real-world collaboration practices  

---

# 🧪 Mid-Trimester Interviews

Around Week 6, students may participate in:
- Mid-trimester interviews  
- Mentor progress reviews  
- One-on-one discussions  

Students should prepare:
- Contribution evidence  
- Screenshots  
- GitHub contributions  
- Pull Requests  
- Documentation updates  
- UI or feature contributions  

The purpose of these interviews is to:
- Review progress  
- Provide feedback  
- Identify improvement areas  
- Ensure students are on track  

---

# 🎯 HD Students

Students aiming for HD grades may:
- Be added to HD review/panel groups  
- Participate in additional review discussions  
- Attend interviews with the Product Owner (PO)  
- Present evidence of their contributions  

HD students are generally expected to demonstrate:
- Consistent contributions  
- Initiative and ownership  
- Strong communication  
- High-quality deliverables  

---

# 🧠 Common Challenges During Week 4–6

Contributors may:
- Accidentally break UI layouts  
- Push incomplete work  
- Struggle with GitHub workflows  
- Misunderstand reusable components  

---

# ✅ How to Overcome These Challenges

- Work on separate branches  
- Follow existing code patterns  
- Test changes before pushing  
- Ask for reviews early  
- Communicate blockers quickly  

---

# 📅 Week 7–9 — Independent Contributions & Collaboration

---

# 🚀 More Meaningful Contributions

By this stage, contributors are expected to work more independently and contribute more meaningfully to the project.

Examples include:
- Designing new pages  
- Implementing features  
- Improving workflows  
- Refining user experience  
- Supporting documentation improvements  

Students may begin taking ownership of assigned tasks.

---

# 👥 Collaboration Expectations

Contributors are expected to:
- Collaborate respectfully with team members  
- Attend meetings regularly  
- Share updates consistently  
- Respond to feedback professionally  
- Support team workflows and deadlines  

Communication remains extremely important throughout this stage.

---

# ⚠️ Common Challenges During Week 7–9

Students may:
- Submit incomplete work  
- Ignore feedback  
- Work without clarifying requirements  
- Miss communication updates  

---

# ✅ How to Overcome These Challenges

- Clarify requirements early  
- Keep communication active  
- Follow Figma carefully  
- Test changes before submitting work  
- Accept feedback positively  

---

# 📅 Week 10–12 — Finalisation & Delivery

---

# 🏁 Final Contributions

During the final weeks, contributors should focus on:
- Final refinements  
- Bug fixing  
- Documentation completion  
- Testing and stability  
- Presentation preparation  
- Final reviews and clean-up  

Students should avoid risky or large last-minute changes unless necessary.

---

# 👥 Final Meetings & Reviews

Contributors may participate in:
- Final mentor meetings  
- Final review discussions  
- Stream review sessions  
- Presentation preparation meetings  

These sessions are important for:
- Ensuring submission readiness  
- Finalising contributions  
- Reviewing remaining issues  

---

# 🧠 Final Advice for Contributors

Throughout the trimester:
- Communicate consistently  
- Keep evidence of contributions  
- Start tasks early  
- Ask for help when needed  
- Stay involved in meetings and discussions  

Small and consistent contributions are significantly better than rushed work near deadlines.

---

# 💡 Best Practices

## ✅ Do
- Ask questions early  
- Attend meetings regularly  
- Start with smaller tasks  
- Keep documentation updated  
- Follow design guidelines carefully  
- Test changes before pushing  

---

## ❌ Avoid
- Making large changes without understanding the project  
- Ignoring feedback  
- Missing meetings regularly  
- Delaying communication  
- Pushing untested code  
- Overcomplicating UI designs  

---

# ⚠️ Things to Watch Out For

Common issues observed in previous trimesters include:
- Poor communication  
- Missing responsiveness in UI  
- Ignoring accessibility considerations  
- Inconsistent documentation  
- Lack of progress updates  
- Working without understanding requirements  

Contributors should actively avoid these issues throughout the trimester.

---

# 🎯 Expectations from Contributors

Contributors are expected to:
- Be proactive  
- Communicate clearly  
- Show consistent weekly progress  
- Participate professionally  
- Collaborate respectfully  
- Take ownership of assigned tasks  

The project values teamwork and communication just as much as technical contributions.

---

# 🏁 Final Note

You are not expected to know everything immediately.

The purpose of this project is to:
- Learn collaboratively  
- Build practical experience  
- Improve technical and communication skills  
- Contribute gradually and confidently  

Focus on:
- Learning  
- Communication  
- Consistency  
- Collaboration  

Progress over perfection.
